# Project Delivery & Release Checklist

This checklist is intended for Delivery Leads, Project Coordinators, Release Managers, and Quality Advocates to ensure consistent readiness for releases and major deliveries.

## Pre-release (2–4 weeks before release)
- [ ] Confirm scope for release and freeze policy communicated
- [ ] Identify and assign Risk Owners for top risks
- [ ] Ensure acceptance criteria for features are documented
- [ ] Confirm test plans and automation coverage targets
- [ ] Schedule stakeholder demos and communications

## Release Week
- [ ] All critical and high-severity defects are triaged and assigned
- [ ] Release notes drafted and reviewed
- [ ] Deployment runbook prepared and tested in staging
- [ ] Rollback plan validated
- [ ] Stakeholders notified of release window
- [ ] Final signoff from Product Owner and Quality Advocate

## Post-release
- [ ] Monitor key metrics and incidents for 72 hours
- [ ] Collect stakeholder feedback and log actionable items
- [ ] Conduct a short retrospective focused on process improvements
- [ ] Close change requests and update documentation

Suggested owners:
- Project Coordinator — update trackers and meeting notes
- Delivery Lead — confirm delivery readiness
- Quality Advocate — signoff on acceptance criteria
- Release Manager — execute deployment and validate production health
